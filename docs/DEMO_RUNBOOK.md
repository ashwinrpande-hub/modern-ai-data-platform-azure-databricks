Five stations, ~2–3 minutes each. Pre-demo checklist at the bottom. Every claim in the
deck maps to something you can open live at one of these stations.

## Station 5 — Agent evidence (the differentiator)
```sql
SELECT agent, mode, status, finished_at FROM acme_bronze.audit.agent_runs ORDER BY finished_at DESC;
SELECT agent, title, body FROM acme_bronze.audit.agent_reports ORDER BY created_at DESC LIMIT 3;
```
Read aloud from the DQ RCA report: the agent verified the failure itself, traced it to
source-side staleness (fresh `_ingest_ts`, frozen business dates, one snapshot batch),
and proposed the bronze-layer check that would have caught it two months earlier. Since
2026-08-14 every report also carries an **Evidence log** (the actual queries + returned
values) and an **Independent verification** section — a second, separate Claude call that
fact-checks the first pass's claims against that evidence before the report saves. Read that
section aloud too if asked "how do you know it isn't making this up."
**Talking point:** "The agent's only tool is read-only SQL; every query it ran — and what it
returned — is in the report itself, not just the decision log; a second model checks the
first one's claims against that evidence before anything saves. That's the guardrail model."
Then: `acme_products.sales.order_to_cash` — a view an agent created from a natural-language
request, through a validation gate; mention `dry_run=true` as the opt-in Plan-Mode path if
asked how a human reviews before a write happens.
